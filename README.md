# Cashback Merge

Java-приложение для симуляции и анализа игровых кэшбэк-кампаний на основе механики 2048. Плитки с одинаковым процентом кэшбэка объединяются, автоматические игроки проходят партии, а симулятор рассчитывает награды и проверяет ограничения кампании.

Проект позволяет сравнивать настройки кампаний и стратегии игроков на большом числе партий, получать статистику в JSON и HTML и воспроизводить отдельные игры.

## Возможности

- Игровой движок со сдвигами и слияниями плиток в четырёх направлениях.
- Размер поля, лимит ходов, вероятности появления плиток и таблица наград задаются через JSON.
- Две стратегии автоматического игрока: случайная и жадная по приросту score.
- Массовые симуляции с распределениями наград и максимальных плиток.
- Проверка доли игроков, достигших заданного уровня награды.
- Сравнение нескольких кампаний при одинаковых seed, числе игроков и стратегии.
- JSON-отчёты для дальнейшей обработки и автономные HTML-отчёты для просмотра в браузере.
- Сохранение и воспроизведение партии по конфигурации, seed и списку ходов.
- Воспроизводимые эксперименты и генеративные тесты игровой логики.

Основной сценарий — автоматическая симуляция. Управление игрой с клавиатуры не предусмотрено.

## Как работает модель

### Игровые правила

- Поле квадратное, минимальный размер — `2×2`. В начале появляются две плитки.
- Доступны направления `UP`, `DOWN`, `LEFT`, `RIGHT`.
- При движении одинаковые плитки объединяются: `1% + 1% → 2%`.
- За один ход плитка участвует максимум в одном слиянии:
  `[1, 1, 2, 0] → LEFT → [2, 2, 0, 0]`.
- После успешного хода появляется одна новая плитка и расходуется один ход из лимита.
- Ход без изменения поля отклоняется: новая плитка не появляется, лимит не расходуется.
- Score равен сумме значений плиток, полученных при слияниях. Сдвиги и появление новых плиток его не увеличивают.
- Партия завершается, когда исчерпан лимит или нет допустимых ходов. Достижение `32%` само по себе игру не останавливает.

### Стратегии

| Стратегия | Поведение |
|---|---|
| `random` | Случайный выбор одного из допустимых направлений |
| `greedy-score` | Выбор хода с максимальным непосредственным приростом score |

Жадная стратегия оценивает ходы на копиях поля без изменения состояния партии и генератора случайных чисел. При равном приросте выбирается первое допустимое направление; поиск на несколько ходов вперёд не выполняется.

### Награды и ограничения

Награда определяется по наибольшему уровню таблицы, не превышающему максимальную плитку партии. Например, в приложенных конфигурациях плитка `16%` соответствует награде `500`, а `32%` и выше — `2000`.

Симулятор считает долю партий, у которых выбранный уровень награды не ниже `maxRewardCashback`, и сравнивает её с `maxRewardAllowedRate`:

- `OK` — доля не превышает ограничение;
- `FAILED` — ограничение превышено.

`FAILED` в отчёте — результат проверки баланса кампании, а не ошибка выполнения программы.

Вероятности и награды хранятся в `BigDecimal`; случайный выбор плиток использует целочисленные веса `BigInteger`. Ограничение проверяется без предварительного округления доли. Для отчёта доля округляется до десяти знаков после запятой.

## Конфигурация кампании

Готовые конфигурации находятся в папке `config/`:

| Файл | Лимит ходов | Сценарий |
|---|---:|---|
| [campaign.example.json](config/campaign.example.json) | 100 | Базовый пример конфигурации |
| [campaign.conservative.json](config/campaign.conservative.json) | 32 | Кампания с небольшим лимитом ходов |
| [campaign.balanced.json](config/campaign.balanced.json) | 36 | Промежуточный вариант |
| [campaign.generous.json](config/campaign.generous.json) | 60 | Кампания с увеличенным лимитом ходов |

В этих конфигурациях вероятность появления `1%` равна `0.85`, а `2%` — `0.15`. Допустимая доля достижения максимальной награды — `0.20`.

| Поле | Назначение |
|---|---|
| `boardSize` | Размер стороны поля, целое число больше 1 |
| `movesLimit` | Положительный лимит успешных ходов |
| `spawnRules` | Значения новых плиток и вероятности их появления; сумма вероятностей должна быть равна 1 |
| `rewardTable` | Соответствие уровней плиток и наград |
| `maxRewardCashback` | Пороговый уровень награды для проверки кампании; должен присутствовать в таблице |
| `maxRewardAllowedRate` | Допустимая доля игроков, значение от 0 до 1, не включая 0 |

Размер поля и условия кампании можно менять в конфигурации без изменения игрового движка.

## Команды

### Симуляция одной кампании

Случайная стратегия, JSON-отчёт:

```powershell
.\gradlew.bat run --args="simulate --config config/campaign.balanced.json --players 10000 --strategy random --seed 42 --output report.json"
```

Жадная стратегия, HTML-отчёт:

```powershell
.\gradlew.bat run --args="simulate --config config/campaign.balanced.json --players 10000 --strategy greedy-score --seed 42 --output report-greedy.html"
```

Параметры `simulate`:

| Параметр | Значение по умолчанию | Назначение |
|---|---|---|
| `--config` | `config/campaign.example.json` | Конфигурация кампании |
| `--players` | `10000` | Количество партий, больше 0 |
| `--strategy` | `random` | `random` или `greedy-score` |
| `--seed` | `42` | Общий seed симуляции |
| `--output` | `report.json` | Путь к выходному отчёту |
| `--replay-player` | `-1` | Номер сохраняемой партии, начиная с 1; `-1` отключает запись |

### Сравнение кампаний

Сравнение трёх готовых конфигураций:

```powershell
.\gradlew.bat run --args="compare --players 10000 --strategy random --seed 42 --output comparison-random.html"
.\gradlew.bat run --args="compare --players 10000 --strategy greedy-score --seed 42 --output comparison-greedy.html"
```

Свой список конфигураций передаётся через запятую без пробелов:

```powershell
.\gradlew.bat run --args="compare --configs config/campaign.balanced.json,config/campaign.generous.json --players 10000 --strategy greedy-score --seed 42 --output comparison.json"
```

Без `--configs` сравниваются `conservative`, `balanced` и `generous`. Параметры `--players`, `--strategy`, `--seed` и `--output` имеют те же значения по умолчанию, что и у `simulate`. Запись replay доступна только в `simulate`.

### Сохранение и воспроизведение партии

Сохранить пятую партию из симуляции:

```powershell
.\gradlew.bat run --args="simulate --config config/campaign.balanced.json --players 1000 --strategy random --seed 42 --output report.json --replay-player 5"
```

В рабочей папке появится `replay.json` с полным конфигом, seed выбранной партии и последовательностью успешных ходов.

Воспроизведение:

```powershell
.\gradlew.bat run --args="replay --input replay.json"
```

Команда печатает начальное поле и состояние после каждого хода. Стратегия не выбирает ходы заново, а изменения исходного файла конфигурации не влияют на сохранённую запись. При одинаковых конфиге, seed и ходах воспроизводятся те же поля и score в текущей реализации.

### Просмотр начального поля

Запуск без подкоманды создаёт и печатает начальное поле:

```powershell
.\gradlew.bat run
.\gradlew.bat run --args="42 config/campaign.balanced.json"
```

Позиционные аргументы — seed и путь к конфигурации. Без аргументов используются `42` и `config/campaign.example.json`.

## Отчёты и примеры результатов

Отчёт одной кампании включает:

- параметры запуска: число игроков, лимит ходов, seed и стратегию;
- распределение максимальных плиток;
- распределение наград;
- средний и максимальный score;
- долю достижения порогового уровня награды и статус `OK` / `FAILED`.

Расширение `.html` включает HTML-формат; остальные расширения сохраняют JSON. HTML-отчёты автономны и открываются без сервера или внешних ресурсов. Файлы записываются в UTF-8.

Относительные пути считаются от корня запуска. Существующий выходной файл перезаписывается; родительская папка должна существовать. Запись выбранной партии всегда сохраняется в `replay.json` рабочей папки.

Примеры из сохранённых отчётов: **10 000 партий, seed 42, ограничение 20%**.

| Кампания | Ходов | Random: доля / статус | Greedy-score: доля / статус |
|---|---:|---|---|
| conservative | 32 | 0,21% / OK | 2,90% / OK |
| balanced | 36 | 2,31% / OK | 15,57% / OK |
| generous | 60 | 75,32% / FAILED | 92,70% / FAILED |

В этой выборке увеличение лимита ходов повышает долю максимальной награды, а жадная стратегия достигает её чаще случайной. Результаты относятся к указанным конфигурациям и seed.

Сохранённые отчёты: [Random](reports/comparison-random.html), [Greedy-score](reports/comparison-greedy.html).

## Архитектура

| Компонент | Ответственность |
|---|---|
| `Main` | Выбор команды и разбор параметров запуска |
| `Load` | Чтение JSON, сериализация отчётов и replay, запись файлов |
| `config` | Records конфигурации, правил появления плиток и уровней наград; валидация входных данных |
| `GameState` | Поле, алгоритм сдвигов и слияний, score и лимит ходов |
| `GameSession` | Генерация плиток, выполнение ходов и определение награды |
| `Player`, `RandomPlayer`, `GreedyScorePlayer` | Общая модель автоматического игрока и реализации стратегий |
| `Simulator` | Запуск партий, агрегация статистики и сравнение кампаний |
| `HtmlReport` | Формирование HTML-отчётов |
| `ReplayData`, `Replay` | Данные записи и воспроизведение последовательности ходов |

Игровое состояние, стратегии, симуляция и файловый ввод-вывод разделены. Конфигурации и результаты представлены records с защитными копиями коллекций.

## Тестирование и качество кода

Тесты проверяют конфигурации, воспроизводимость по seed, правила слияния, направления движения, расчёт score, награды, агрегацию статистики и запуск CLI.

Для merge-логики реализованы генеративные проверки на JUnit:

- случайные поля размером от `2×2` до `8×8` для всех четырёх направлений;
- полный перебор коротких строк из значений `0`, `1`, `2`, `4`;
- случайные последовательности ходов;
- сравнение с независимым эталонным алгоритмом;
- проверка сохранения суммы плиток, корректного начисления score и отсутствия изменений при проверке доступности хода.

Запуск всех тестов:

```powershell
.\gradlew.bat test
```

Только генеративные проверки:

```powershell
.\gradlew.bat test --tests "*MergePropertiesTest"
```

Сборка и все проверки:

```powershell
.\gradlew.bat --continue assemble check printCoverage
```

Автоматическое форматирование:

```powershell
.\gradlew.bat spotlessApply
```

HTML-отчёты после тестирования:

- результаты тестов: `build/reports/tests/test/index.html`;
- покрытие JaCoCo: `build/reports/jacoco/test/html/index.html`.
